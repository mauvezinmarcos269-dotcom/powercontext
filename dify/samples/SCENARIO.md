# 评审样例：赖不掉的尖叫鸡

初始条件：按 README 部署并导入唯一 DSL，PowerContext、杂货铺、Dify 正在运行。使用一个从未游玩过的 API `user`，或在 Dify WebApp 中输入 `重开`。初始店币 10、记仇 0、好感 0、未获得月亮。

| 步骤 | 输入与操作 | 预期结果 |
| --- | --- | --- |
| 1 | `恶作剧 把招财猫换成尖叫鸡` | 老板即兴吐槽；店币 11、记仇 2、好感 0，月亮价 12；显示新 PowerContext Artifact ID |
| 2 | **新建 Dify 会话**，保持同一浏览器／API user，输入 `看看 老板你还记得我吗？` | 台词针对尖叫鸡或招财猫回应；数值不变；本轮读取的 Artifact ID 等于上轮写入 ID |
| 3 | `帮忙` | 店币 13、好感 1、记仇 2 |
| 4 | `送礼` | 店币 11、好感 3、记仇 1 |
| 5 | `送礼` | 店币 9、好感 5、记仇 0；月亮价 3 |
| 6 | `买月亮` | 支付 3，剩 6 店币，展示「冤家熟客」结局 |
| 7 | 更换 API user／使用另一浏览器身份，输入 `看看` | 新玩家初始 10 店币，不知道前一玩家的恶作剧，显示首次进店 |
| 8 | 回到原玩家输入 `重开` | 初始 10 店币、0 记仇、0 好感；新快照序号继续递增，旧数值不再影响本局 |

每轮台词是开放式生成，不要求逐字相同。主要核对规则数值、具体恶作剧对台词的影响和读取／写入凭证。

自动体验：`python samples/verify_dify.py`。它为本次运行生成随机新用户，并在**每一轮**建立新 Dify 会话，输出完整回答和各节点执行状态到 `evidence/dify-run.json`。证据不包含模型 API Key、管理员密码、后端 API Key 或签名票据。

复现初始状态：原玩家输入 `重开`；或换一个全新的 API `user`。不要删除全局数据来重置单个玩家。
